# Saving a document

A PDF is saved by rewriting it or by appending the changes to it (ISO 32000-2:2020, 7.5.6). `save(sink)` with the default `SaveOptions.mode`, `SaveMode::Rewrite`, is a streamed full rewrite of the objects reachable from the trailer, and nothing else. `SaveMode::Incremental` writes the source's bytes, then appends the changes; `SaveMode::InPlace` appends only the changes to the opened file, unchanged since open. Neither falls back to a rewrite; each fails with the reason. A rewrite of reachable objects is the right default because it is the only save after which deleted content has left the file; incremental stays available because signatures need it and it is the cheap path for large files.

A save that fails halfway can destroy the only copy. Saving over the opened file writes beside it, then renames, resolving a symlink first and keeping the file's permissions; `SaveMode::InPlace` has no atomic guarantee and the API says so. A failed save to a path leaves the previous file intact; to an arbitrary sink it may leave partial output. Users expect a saved path to hold either the old file or the new one, never half of each, and a rename that replaced a symlink or reset permissions would be a silent change.

Some work touches every object. Whole-file work (compress, linearize, encrypt) is a save option, not an edit; linearizing and signing need a file sink or temporary storage and otherwise fail with a code. As an edit it would put the whole file in the overlay, and linearizing and signing both patch bytes already written.

Removal needs old bytes gone; a signature needs them untouched. Redaction and sanitizing refuse an incremental save. Rewriting signed input needs `SaveOptions.break_signatures`, and what a save does to each signature is reported separately (ISO 32000-2:2020, 12.8). Removed content must leave the file, and a user asking to preserve signatures must get a refusal, not a broken signature.

A session often outlives many saves. Saving never changes the logical document, so held pages stay valid; after a successful save to the opened file the session's source becomes the saved revision and the overlay is released; saving elsewhere leaves the session on its source. Hundreds of edit-and-save rounds must not retain history, and saving a copy must not silently switch the session to another file.
