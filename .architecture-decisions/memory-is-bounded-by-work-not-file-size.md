# Memory is bounded by work, not file size

A 1 GB file can cost another 1 GB in three places: reading it in, building its objects in memory, and building the output before writing it. Library memory grows with what is touched and changed, never with the file's bytes: a cache with a limit the caller sets, the overlay of changes, the buffers of the active operation, and per-object bookkeeping. This rule cannot be added later: an API designed without it returns whole things, and callers come to depend on that.

Four things need an entry per object, and object count grows with file size: the index of object offsets, a merge's renumbering map, and a save's set of reachable objects and its cross-reference table. Offsets are read from the source's own cross-reference data on demand where the file allows; what must be held costs a few bytes per object, counts against the resource policy, and spills or fails like any other work. Ten million objects at an uncounted 100 MB would break the rule in the one place a test file of a few large streams never shows.

A 1 KB stream can decompress to gigabytes. A resource policy passed at open sets the cache limit, decoded-data limit, nesting depth, object count, concurrency and temporary storage (off, or a directory with a quota; in the browser, one in the origin private file system); it counts library allocations only, not caller buffers, runtimes or OS caches. Documents opened with the same policy share its budget, and work is charged to the document that asked for it, also when it reads another document's backing. Limits with safe defaults are the only way untrusted input never exhausts memory, and a budget per policy lets a server cap its documents together or each alone.

Honest work can hit a limit too, such as a merge of many objects. Exceeding a limit fails with a stable error code unless temporary storage is allowed, in which case work spills there and is removed on close or cancel; temporary storage is off by default. Configurable spill trades disk and speed for predictable RAM, and off by default means the library never writes files the caller did not ask for.

A memory promise that no test measures decays with the first convenient buffer. The memory rule is tested by editing and saving two virtual 1 GB files generated on the fly, one of a few large streams and one of millions of small objects, through a source that counts bytes read, with allocations counted; the bound is fixed after the first measurement and no public "1 GB costs X MB" figure is promised. A number invented before measuring is wrong, and the test, not the number, is what keeps the promise.

Every binding crosses a boundary where a whole-buffer copy can hide. There is no 1.0 before open → inspect → rotate → save → reopen, then a merge of two file-backed sources, passes that test in Rust, Python, C and the browser. A contract untested in the C and browser bindings is a contract on paper.
